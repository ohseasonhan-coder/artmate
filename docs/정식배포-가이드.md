# 아트메이트 AI — 정식 버전 배포 가이드 (Supabase 연결)

이 문서대로 따라 하면 **데모 모드 → 실제 Supabase 백엔드로 동작하는 정식 버전**으로 전환됩니다.
⚠️ API 키는 **본인만** 다루세요. 키를 채팅/코드/깃허브에 올리지 마세요. (`.env.local`과 Vercel 환경변수에만 입력)

> 현재 단계 범위: **로그인 없이 동작하는 영역**(둘러보기·공개 프로필·섭외 문의 저장·페이지 빌더·이미지 업로드)을 실데이터로 전환합니다.
> 로그인 기반 사용자별 대시보드는 다음 단계에서 붙입니다.

---

## 1. Supabase 프로젝트 생성

1. https://supabase.com 접속 → 로그인(깃허브 계정 가능)
2. **New project** 클릭
3. 입력:
   - **Name**: `artmate` (자유)
   - **Database Password**: 강한 비밀번호 생성 후 **따로 보관** (DB 직접 접속용, 평소엔 안 씀)
   - **Region**: `Northeast Asia (Seoul)` 권장
4. **Create new project** → 1~2분 대기

---

## 2. API 키 확인 (Project Settings → API)

좌측 톱니바퀴(Project Settings) → **API** 메뉴에서 3개 값을 복사합니다.

| Supabase 화면의 이름 | 넣을 환경변수 | 성격 |
|---|---|---|
| Project URL | `NEXT_PUBLIC_SUPABASE_URL` | 공개 가능 |
| `anon` `public` | `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 공개 가능 |
| `service_role` `secret` | `SUPABASE_SERVICE_ROLE_KEY` | **비밀! 절대 노출 금지** |

> `service_role` 키는 모든 보안정책(RLS)을 우회합니다. 서버(페이지 빌더 저장·이미지 업로드)에서만 쓰이며, 브라우저에 절대 노출되지 않도록 코드가 설계돼 있습니다.

---

## 3. 데이터베이스 스키마 + 시드 실행

좌측 **SQL Editor** → **New query** 에서 순서대로 실행합니다.

1. 저장소의 [`supabase.sql`](../supabase.sql) 전체 복사 → 붙여넣기 → **Run**
   - 테이블(프로필·경력·미디어·문의·일정·활동·사이트설정 등) + RLS 정책 + Storage `assets` 버킷 생성
2. [`supabase.seed.sql`](../supabase.seed.sql) 전체 복사 → 붙여넣기 → **Run**
   - 공개 예술인 3팀(경력·YouTube) 샘플 삽입 → `둘러보기`가 비지 않음

> 시드를 건너뛰면 실제 예술인이 등록되기 전까지 `둘러보기`가 빈 목록으로 보입니다.

---

## 4. Storage 버킷 확인

좌측 **Storage** → `assets` 버킷이 보이고 **Public**인지 확인합니다.
(3번 SQL에서 자동 생성됩니다. 빌더의 이미지 업로드가 여기에 저장됩니다.)

---

## 5. 로컬에서 먼저 확인 (.env.local)

`art/` 폴더에 **`.env.local`** 파일을 만들고 아래를 채웁니다. (이 파일은 git에 올라가지 않도록 이미 설정돼 있음)

```
NEXT_PUBLIC_SUPABASE_URL=복사한_project_url
NEXT_PUBLIC_SUPABASE_ANON_KEY=복사한_anon_key
SUPABASE_SERVICE_ROLE_KEY=복사한_service_role_key

# AI (Gemini 무료 등급) — 설정 시 AI 프로필 생성·개인비서·자연어 검색이 실제 동작
GEMINI_API_KEY=구글_AI_스튜디오_키
GEMINI_MODEL=gemini-2.0-flash

# 관리자 로그인 (강한 값으로 교체 권장)
ADMIN_USERS=master:원하는비번,master1:원하는비번
ADMIN_SECRET=아무_긴_랜덤_문자열
```

> Gemini 키는 https://aistudio.google.com → "Get API key" 에서 무료로 발급합니다.
> 키가 없으면 AI 기능은 자동으로 데모 응답으로 폴백합니다.

실행:
```bash
npm install
npm run dev
```
→ http://localhost:3000 접속.

**정식 전환 확인 포인트:**
- 상단의 주황색 "데모 모드" 배너가 **사라짐**
- `/browse` 에 시드한 예술인 3팀이 뜸 (DB 조회)
- 프로필에서 섭외 문의 제출 → Supabase **Table Editor → inquiries** 에 새 행 생성 확인
- `/admin/builder` 에서 "저장" → 상단 표시가 **"전체 공유"(Cloud)** 로 바뀌고, 다른 브라우저/시크릿창에서도 홈이 동일하게 보임
- 빌더에서 이미지 업로드 → Storage `assets`에 파일 생성

---

## 6. Vercel 환경변수 등록 (운영 배포)

1. Vercel → `artmate` 프로젝트 → **Settings → Environment Variables**
2. 아래 변수를 **Production**(필요시 Preview도) 에 추가:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `SUPABASE_SERVICE_ROLE_KEY` → **Sensitive**(비밀)로 표시
   - `GEMINI_API_KEY` → **Sensitive**(비밀), `GEMINI_MODEL`
   - `ADMIN_USERS`, `ADMIN_SECRET`
3. **Deployments → 가장 최근 배포 → Redeploy** (환경변수는 새 빌드부터 적용됨)
4. 배포 URL에서 5번과 동일하게 확인

---

## 7. 완료 후 상태

| 기능 | 정식 버전 동작 |
|---|---|
| 둘러보기 / 공개 프로필 | Supabase `artist_profiles` 실조회 |
| 섭외 문의 | `inquiries` 테이블에 실제 저장(무가입) |
| 페이지 빌더 / 홈 구성 | `site_config`에 저장 → **모든 방문자 공유** |
| 이미지 업로드 | Storage `assets`에 업로드 |
| AI 프로필 생성·개인비서·자연어 검색 | Gemini 실제 호출 (키 없으면 데모) |
| 관리자 로그인 | `ADMIN_USERS`/`ADMIN_SECRET` 기반 |
